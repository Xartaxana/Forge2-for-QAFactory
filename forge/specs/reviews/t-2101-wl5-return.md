## Findings

**F1 (fix before merge, not blocking) forge/tools/journal.py::main, the `open` branch.** `status, tasks, bad = open_tasks(a.root)` and then `wait = set(pending(load(a.root)[0]))` load the journal twice. open_tasks' own docstring says `loaded` exists "so a caller that read the journal does not read it twice". snapshot.py and session_start.py both pass `loaded`; main is the only caller that does not. Failure scenario: a line is appended between the two reads, for example `accept t-1` arriving after a `return t-1`. The first read lists t-1 as open and the second finds it closed, so `open` prints `t-1` as a plain open task although it is closed. Fix: `loaded = load(a.root)`, then `open_tasks(a.root, loaded)` and `pending(loaded[0])`.

**F2 (residual outside owns, with file; fix this round when the Lead widens owns to forge/tools/retro.py, else a node with an executor) forge/tools/retro.py::own_event, `per_task`.** The count of "retried tasks" adds `reject` and `return` per task. Before this diff a return and a reject were alternative closes. Under FR-1127, as the SKILL step 2 and this diff now have it, a return is always followed by its accept or reject. So a single rejected attempt counts 2, and the task is reported as retried. Witness (trail W2): journal `dispatch, return, reject` on t-1 gives `retried tasks: 1` and `task t-1: 2`. The control `dispatch, reject` gives `retried tasks: 0`. Fix: per_task counts `reject` only. A return is the worker's stop and never an attempt end. The B9 card's definition of "retried" moves with it. The builder's `similar:` line called retro "differs", but it reads the same meaning of `return` that this diff changed.

**F3 (residual outside owns; this round when the Lead widens owns, else a proposed node, owner Lead/designer) the spec cards still say a return closes.** COORDINATOR (6) now contradicts them:
- forge/specs/20261125-forge2-light-factory-spec-part4b.md, B2 "THE WHOLE CLOSED EVENT LIST": "`accept`, `reject`, `return` (the Lead; each closes the task's last open `dispatch`" -- now false for `return`.
- forge/specs/20261125-forge2-light-factory-spec-part5.md, B14 rule 6: "Its open dispatches -> `journal.py --event return ...`", plus "named in the `return` note". A builder of B14 who follows the card leaves every dead session's dispatch RESULT PENDING forever, against COORDINATOR (6), which says reject with `failure_class: tooling; dead session`. The same rule's invariant "a late close by a holder believed dead is always visible" (t-1966 F5) now also needs a late `return` after a close to print `already closed by ...`. Otherwise the builder's ignored-return edge stays silent there.
- forge/specs/20261126-forge2-light-factory-spec-part9.md, B18 (a) / F198: "since the task's last closing event" was written with `return` as a close, so the `--run` window must be re-read.
